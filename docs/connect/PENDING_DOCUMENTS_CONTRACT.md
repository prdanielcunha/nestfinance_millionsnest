# Connect pending document summary

`POST /api/finance-gateway?operation=connect-pending-documents`, Bearer Firebase identity and `x-organization-id`, body exactly `{ financeEntityId }`.

Connect sends the same transient Firebase bearer in `Authorization` and `X-Connect-User-Authorization`, matching the existing MusicScale transport. Only these Connect read operations accept the alternate header when a Hosting/Cloud Run boundary consumes Authorization. A supplied forwarded value takes precedence and must be a single bounded Bearer string; invalid/multiple values fail401. It is still untrusted input: the explicit read adapter verifies the selected Firebase token with revocation, then canonical Hub/RBAC/tenant/entity scope. No transport header confers authority. No tokens are stored or logged. Authenticated cross-app delivery remains a release gate, not established by unit tests.

Delegates the same Universal Evidence count/query implementation through an explicit read-only resolver. Every read requires revoked-token verification, canonical Hub ecosystem access, current organization/member entitlement, `finance.view`, active finance entity and member entity scope. Bound Finance or Connect handoffs require current sessionVersion and cannot be retargeted. No token is minted, relabeled or stripped of its binding. The default Finance read/mutation resolver and native login remain unchanged; Connect-bound tokens are not admitted to financial mutations.

`POST /api/finance-gateway?operation=connect-entities` accepts exactly `{}` plus the same transient identity and requested organization header. It uses the existing accessible-entity selector, after the stronger read-entry authorization above, and returns `{ schemaVersion: 1, organizationId, entities: [{ id, displayName }], limited }`. At most25 entries are returned from the existing bounded200-candidate selector; `limited=true` if the candidate cap or result cap is reached. No automatic selection may assume a limited result is complete. Hidden/inactive entities, tax IDs, balances, bank data and documents are never projected. A subsequent summary always revalidates the selected entity; listing does not grant durable authority.
