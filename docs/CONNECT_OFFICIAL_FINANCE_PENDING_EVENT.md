# NestFinance → Connect: official document.pending operator event

Source is the existing tenant/RBAC-guarded `universalEvidenceClassify` transaction, which already stages the canonical `INBOX_REVIEW_REQUIRED` finance signal. No change to that signal, financial ledger, classification, audit fact or permission. On a successful classification the integration re-reads the official evidence and checks the exact organization, entity, evidence, version, review.status=pending and timestamp (<=7 days).

Default is OFF. A server administrator must configure `NESTFINANCE_CONNECT_PENDING_EVENTS_ENABLED=true`, `NESTFINANCE_CONNECT_SOURCE_EVENT_SECRET` (independent HMAC key >=32 characters, equal to Connect's official `nestfinance` source entry), and `NESTFINANCE_CONNECT_OPERATOR_TARGETS_JSON` (server-controlled org -> {conversationId,recipientUid} for an actual Connect Inbox thread and verified current operator). Missing/invalid mapping fails closed; never take a recipient from client request. Existing official RBAC `finance.create_drafts` is unchanged.

Only `{schemaVersion:1,sourceApp:'nestfinance',eventId,organizationId,conversationId,occurredAt,trigger:'document.pending',recipientUid}` is signed, posted to the existing `Connect /api/core/automations/events/nestfinance`, and accepted only with authenticated HMAC and 202 accepted:true. The event ID is deterministic from tenant, financial entity, evidence and version, without raw document metadata. No tax IDs, values, original filenames, document images, OCR content, customer identities or financial data leave NestFinance. Connect revalidates operator/conversation permissions and uses its queue lease/quota; no outgoing WhatsApp send.

Ambiguous transport and 5xx are not automatically retried, and never alter a successful classification response. This source producer is post-commit best effort; it is **not** a durable Finance-side outbox and cannot yet guarantee recovery of an event lost between transaction and Connect enqueue. The durable canonical Finance signal/fact is the authoritative event for a future verified Tool Gateway/worker adapter. No synthetic domain event is advertised as delivered. No source key, operator mapping or real production acceptance has been installed or validated; do not turn flag ON until then.

`npm run test:connect-pending-events` and `npm run test:finance-cross-app-events` cover tenant/version/consent-proxy contract, cryptographic payload, no PII, stable event ID and no transport re-send. These prove implementation only, not external delivery or physical iPhone notifications. Continue with official secure source trigger for NestJourney and consent/Meta window gating; #226 is still open.
