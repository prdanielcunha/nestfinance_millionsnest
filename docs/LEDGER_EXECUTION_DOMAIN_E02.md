# E02 execution domain foundation

This pure domain boundary validates balanced journal material for income, paid expense, asset transfer and liability settlement. It requires persisted, versioned and entity-scoped account/category/ledger references; preview fallback identifiers are not eligible. Current content, approver, approval/source hash, reference fingerprint, plan hash, period state and exact version are checked again before preparing journal lines and signed account movements.

The pure function has no persistence or HTTP exposure. A separate internal persistence adapter reads approval, configuration, references and period state in the database transaction, and atomically stages journal, source status, movement-only projections, Count source lock, audit, canonical facts and idempotency receipt. No existing product route calls it. The dedicated server flag defaults OFF; this slice does not enable production posting. Projections explicitly exclude opening/total balances.

Local tests cover four balanced cases, 33 rejection/integrity cases and deterministic reference ordering. CI also exercises existing posting-plan/journal regressions and an isolated Java21 Firestore journey: five balanced flows including liability-funded expense, identical concurrent retry, competing actors, exact movement signs, separate opening balance and seven atomic rejection cases. Emulator results must be collected from CI before claiming persistence validated.

Integration still requires independently authorized endpoints, safe initialization of existing histories, real configuration/mapping approval, canonical Count-origin verification, reversal, formal period closure, verified opening balance and protected read models. Reimbursement and cost-center execution deliberately reject until their references can be validated. This is a necessary E02 foundation, not completion or production certification of E02.
