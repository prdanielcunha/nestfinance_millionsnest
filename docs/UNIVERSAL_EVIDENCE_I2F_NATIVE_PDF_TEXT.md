# Universal Evidence I2F — Native PDF Text Extraction Foundation

## Purpose

I2F adds a bounded, deterministic foundation for extracting text already embedded in eligible PDF files. It does **not** expose a new API or UI in this slice.

The extractor uses `unpdf@1.8.1` with its serverless PDF.js build. It processes pages individually through the PDF.js document proxy instead of using a whole-document convenience extraction helper.

## Security and resource boundaries

Before PDF.js runs, the existing I2D structural inspector must classify the document as a supported, non-encrypted PDF with detected text signals, no unsupported non-image streams, and no resource-limit condition.

Hard limits:

- input bytes: 4 MiB;
- pages: 40;
- returned characters: 100,000;
- PDF.js `maxImageSize`: 4,194,304 pixels;
- `disableAutoFetch: true`;
- `disableStream: true`.

The extractor never renders or extracts images.

## Semantics

`state = extracted` means PDF.js produced native text under the supported limits.

`state = unavailable` is fail-closed and includes a machine-readable reason such as:

- `input_too_large`;
- `encrypted`;
- `text_layer_not_detected`;
- `structural_preflight_incomplete`;
- `page_limit_exceeded`;
- `extraction_empty`;
- `parser_error`.

Extracted PDF text is not guaranteed to preserve human reading order or semantic layout. I2F performs no financial interpretation.

## Explicit non-scope

I2F does not:

- create a gateway operation;
- expose a frontend surface;
- persist extracted text;
- use OCR;
- use Gemini or any AI model;
- classify documents;
- recognize CNPJ/CPF, dates, values, Pix, boleto or banks;
- create/update transactions, journals, aggregates, balances, PostingPlans or Count data;
- write Universal Evidence.

A later slice may integrate this certified extractor behind the existing authorization, organization, finance-entity and evidence boundaries.

## Dependency and CI

`unpdf` is pinned exactly to `1.8.1` and the matching `package-lock.json` was generated by npm on a GitHub-hosted Node 22 runner. Release/CI remains `npm ci`.

The canonical Frontend Quality workflow runs `npm run test:universal-evidence-pdf-text-extractor-i2f` in addition to lint/build and existing regression gates.
